**From:** Bratislav Tomic, Product Owner

**Subject:** Project Titan Watch prototype boundary

Team,

I have translated discovery into a proposed demonstration boundary. This is not a
requirements baseline.

The prototype would use one sanitized replay scenario and no live integrations. It
would demonstrate that Apex can bring several source types into a coherent
command-center experience. The primary demonstration path is:

1. observe an emerging signal pattern
2. associate the pattern with one or more known kaiju
3. understand the current regional threat posture
4. focus on the affected geography
5. show response resources changing as the scenario escalates

Open questions remain around source freshness, confirmation, field correction,
assignment acknowledgment, community visibility, and degraded operation. We will not
represent those as solved.

The June date gives us roughly twelve working weeks, including review and rehearsal.

Bratislav

**Subject:** RE: Project Titan Watch prototype boundary

This is feasible if "bring together" means a browser-based simulation.

Proposed technical constraints:

* static kaiju registry records
* generated sensor log based on Amalia's sanitized sample
* client-side scenario state
* no authentication, persistence, agency integration, or operational messaging
* map tiles from an existing basemap provider
* deterministic trigger for the steering demonstration

The highest risk is that a smooth replay looks like a live operational system. We need
the mock boundary in the repository and demonstration notes.

I also recommend treating any classification and summary behavior as a model concept,
not validated intelligence.

Snezhana

The path tells a clear story, but it over-represents command-center control.

Discovery also surfaced:

* dispatchers need to know what changed and what was acknowledged
* field teams need a way to challenge unsafe assumptions
* source health and observation coverage affect meaning
* communities with weak signals can disappear from the picture
* wallboard awareness and desk interaction may need different structures

I support the prototype if we retain these as explicit research gaps and test the
artifact as a hypothesis. I do not support calling the June demonstration a validated
workflow.

Kadijah
